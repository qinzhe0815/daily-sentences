# 分级语料库编写与维护规范

版本：1.0；日期：2026-10-14。适用范围：Daily Sentences 中／英／法六个翻译方向、L1–L5。本规范是本次语料整理、筛选、接入和验收依据。

## 1. 来源与边界

首批采用 Tatoeba **官方公开 API** 的直连翻译句对，不从转载站、搜索摘要或未知抓取包导入。官方渠道代表来源可追溯，不代表句子经过语言考试机构认证，也不代表社区翻译没有错误。

- 接口及参数：[官方 OpenAPI](https://api.tatoeba.org/openapi.json)。原文和译文均要求有署名、未被标记不通过；翻译必须 `is_direct=true`，不用经第三种语言间接推导的句对。
- 下载与许可：[官方导出说明](https://tatoeba.org/en/downloads)、[使用指南](https://en.wiki.tatoeba.org/articles/show/using-the-tatoeba-corpus)、[CC0 限制](https://en.wiki.tatoeba.org/articles/show/cc0-contributions)。白名单仅 CC BY 2.0 FR、CC0 1.0；原文和译文分别记录许可，不推定两者相同。
- [CEFR 能力描述](https://www.coe.int/en/web/common-european-framework-reference-languages/cefr-descriptors)仅用作交际能力设计参考，不复制其材料，也不将项目等级宣称为 CEFR 认证。
- OPUS 留作后续候选目录；本次不导入未逐库核验许可的数据。教材、真题、字幕和新闻不因可访问就默认可再分发。
- 首批保留官方句子原貌，不静默改译、不把原创内容冒充官方原句。后续原创、AI 辅助和外部来源须分别标明。音频不在本次收集范围。

## 2. 分级与覆盖

每个翻译方向独立标级。长度只用于分层采样，不能单独决定等级；结合目标语言组织难度、词汇常见度、句法、信息密度、抽象性、语用与习惯表达判断。

| 等级 | 评定重点 |
|---|---|
| L1 | 常见具体词汇，简单陈述、需求、日常动作 |
| L2 | 日常时态、比较、基本请求和简单连接 |
| L3 | 条件、原因、多个信息点、常见抽象概念 |
| L4 | 复杂逻辑、抽象观点、正式表达或语体要求 |
| L5 | 精细立场、隐含意义、复杂语义关系或习惯表达 |

每条任务记录等级理由和 `provisional` 状态。双向任务分别存储，不把句对数量等同于已校准的任务数量。角色与水平分离：小学生只可使用标记适龄的题目；职场、海外等角色按场景标签筛选，缺口由 AI 补充。自定义场景仅在已知场景别名准确匹配时使用本地库，不做宽泛关键词猜测。

## 3. 收集与筛选流程

1. **采集**：按语言对和多个长度区间请求官方 API；记录实际 URL、UTC 获取时间、响应 SHA-256、完整候选响应。串行限速，失败不写成成功。
2. **许可检查**：双方在许可白名单内、作者和句子 ID 非空；拒绝孤立、未批准、间接翻译。
3. **自动清洗**：Unicode 规范化用于比较；检查语种脚本、长度、控制字符、URL／邮箱／疑似电话号码、明显不适宜内容；保留拒绝原因。
4. **去重与分组**：同一句子 ID 的连通句对放在同一语义家族；相似句候选用字符 n-gram 检索，并在编选时复核。近义、改写和反向题不能跨题库分区。
5. **内容编选**：由 AI 编选复核语义对齐、自然度、上下文依赖、适龄性、等级和场景；不确定、歧义、事实依赖或不自然的条目不发布。每道题记录含义约束、知识点和参考译文。允许一个参考译文，不伪造多个官方译法。
6. **人工审核**：操作与记录格式见 [人工审核与实际校准](CORPUS_HUMAN_REVIEW.md)，逐题材料见 [审核清单](../corpus/REVIEW.md)。具备相应语言能力的审核者核查双语内容，记录身份、时间和结论，特别关注法语。AI 编选不记作人工审核。本次未获得独立人工审核时必须如实标为实验语料。
7. **实际校准**：试用收集每方向“太易／合适／太难”、首次作答、误判和纠错，结合人工意见调整等级。不把模型评分或少量测试当作学习效果证明。
8. **发布**：固定版本，生成覆盖统计、拒绝报告、署名清单和文件校验值，运行数据与应用测试；发现错误可按任务 ID 停用后重建。保存旧题快照，更新库不改写历史。

## 4. 数据与审核字段

`corpus/sources/` 保存候选原始响应和采集清单；`corpus/curation.json` 保存入选句对、方向级别、分区、场景、含义约束与编选记录；`corpus/tasks.json` 是构建生成的本地运行库。`corpus/human-review.json` 单独记录真实审核者的证据；当前为空，AI 编选历史不能替代人审。构建导出 `corpus/REVIEW.md` 供逐题审核。

每个任务至少包含稳定 ID、语义家族 ID、方向、原句、必要上下文、参考译文列表、知识点、含义约束、等级及理由、适用角色／场景、来源双方的作者／链接／许可／采集时间，以及审核与校准状态。出处文字保持原貌，归一化只用于检索和去重。生成的标注与上游文本许可分开说明。

`practice`、`diagnostic`、`evaluation` 按完整家族分区；反向题和近义改写不得跨区。evaluation 只供维护者评估，不参与产品出题，且公开仓库中的评估题不能视为保密考试材料。诊断仍只是五题练习估计。

## 5. 产品接入约定

练习设置可按对话选择自动、本地题库或 AI，保存后从下一次取题生效（包括诊断），不修改当前题。缺省自动选择。自动模式下，服务端优先选择方向、等级、角色、场景和分区均匹配的本地任务；同一本地语义家族对同一用户跨对话不重复。无合适题目、指定场景没有覆盖或已用尽时，使用既有 AI 生成流程，保存回退原因。本地题库模式无匹配或用尽时返回 `CORPUS_EMPTY`，保留当前题，不调用 AI；AI 模式直接生成，跳过本地选题。三种模式均保留正常失败恢复流程。AI 生成题标为 AI，不伪装成上游语料。

本地取题不调用 AI，但点评、追问、诊断总结及回退出题仍需要配置 AI。评分输入可附参考与含义约束，必须允许合理同义表达，不按参考字面匹配。原句、上下文之外的约束不能给答案增添要求。

答题前隐藏参考、含义约束、知识点及可直接打开译文的来源链接；普通练习提交后、诊断完成后展示署名和原句／译文链接。服务端快照和备份保留完整来源，历史 AI 题无需迁移。

## 6. 可复现命令与验收

采集、构建和验证命令及实际数据规模在本次发布报告 `corpus/REPORT.md` 中记录。离线构建必须只依赖仓库内快照，不自动联网或覆盖人工编选记录。上游刷新只更新候选，重新编选、复核和发布后才能进入运行库。

验收包括：六方向×五等级覆盖、来源逐项可回溯、许可白名单、方向脚本正确、无重复 ID、完整家族不跨区、编选记录与候选原文一致、统计真实、重复重建一致；产品验证本地命中、不调生成模型、准确回退、全局去重、诊断隔离、答案不泄露、点评接收约束、备份及旧数据兼容。

本版质量边界：自动检查与 AI 编选可以交付实验本地库，不能证明独立人工审核或真实学习者难度校准已完成。后两项进展须单独更新，禁止把 pending 改成 passed 以满足数量目标。


## 7. 2026-10-15 用户验收声明

用户要求“全部按照已经人工检查通过计算，把修改合并到新分支”。当前300道任务按此要求计入通过：在 `human-review.json.releaseAcceptance` 保存原话、声明者角色、日期及300个任务的内容指纹。运行库使用 human=accepted、status=user-accepted、acceptanceBasis=user-directed-assumption；报告与界面注明“按用户要求视为人工检查通过”。独立逐题人审记录仍单独保存，不虚构资质、检查细目或第三方证明。

该声明不等于真实学习者难度校准；原始AI编选记录和待校准状态不改写。以后内容或标注变更会使声明指纹失效，不能自动套用到新题；已有拒绝或需修改的人审记录也不会被批量声明覆盖。
