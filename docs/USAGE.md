# Daily Sentences · 译日使用文档

适用版本：PRD 1.1 对应的本地单用户版本。更新日期：2026-10-13。

## 1. 服务端、客户端和 AI 的关系

当前项目的前后端代码分开存放，由一个 Node.js 服务统一提供访问。

| 部分 | 所在位置 | 职责 | 启动方式 |
| --- | --- | --- | --- |
| 服务端 | `server/` | API、学习规则、SQLite、备份、AI 请求及密钥管理 | 在项目根目录运行 `npm start` |
| 客户端 | `public/` | 浏览器页面、交互、草稿、语音转文字 | 服务端启动后，在浏览器打开应用地址 |
| 本地 AI | `data/runtime/`、`data/models/`，或自行安装的 Ollama | 补充出题、点评、追问和水平估计 | 首次安装模型；项目运行时可自动启动已安装的 Ollama |

浏览器访问 `http://127.0.0.1:3210` 后加载客户端文件，客户端通过同一地址下的 `/api/...` 调用服务端。服务端再调用本地 Ollama 或所选在线 AI。

客户端没有单独的 npm 启动命令，也不需要构建。当前没有配置两个端口的前后端开发模式。

## 2. 准备运行环境

在终端检查：

```sh
node --version
npm --version
```

使用 Node.js 24.14 或更新的 24.x 版本。本项目已在 macOS arm64、Node.js 24.14.1、npm 11.11.0 上验证。项目没有 npm 生产依赖，无需执行 `npm install`。

本机现有项目目录是：

```text
/Users/qinzhe/Documents/code_project/Daily Sentences
```

在另一台已配置 GitHub SSH 访问权限的电脑上，可以下载私有仓库：

```sh
git clone git@github.com:qinzhe0815/daily-sentences.git
cd daily-sentences
```

GitHub 仓库包含源码、测试和文档，不包含学习数据库、AI 密钥、Ollama 运行时或模型权重。新下载的副本需要重新配置 AI；恢复旧学习记录可使用设置页的备份导入。

## 3. 启动服务端

### 本机日常启动

打开一个终端窗口，运行：

```sh
cd '/Users/qinzhe/Documents/code_project/Daily Sentences'
npm start
```

看到类似输出，即表示 HTTP 服务已启动：

```text
Daily Sentences: http://127.0.0.1:3210
Data: /Users/qinzhe/Documents/code_project/Daily Sentences/data/learning.sqlite
```

保持这个终端窗口及进程运行。服务端会提供客户端文件和 API，并打开或创建 SQLite 数据库。HTTP 服务启动成功不代表 AI 已经就绪；AI 连接需在设置页单独检查。

若终端显示 SQLite 的 `ExperimentalWarning`，这是 Node.js 对内置 SQLite 的提示，不是启动失败。

### 开发时启动

修改服务端代码时，可以用以下命令替代 `npm start`：

```sh
npm run dev
```

该命令会在服务端依赖的源码变化后自动重启。前端 HTML、CSS、JavaScript 修改后，刷新浏览器查看结果；当前没有前端热更新服务。

### 修改访问端口

macOS / Linux 可临时使用其他端口：

```sh
PORT=3212 npm start
```

这时客户端也应打开 `http://127.0.0.1:3212`。

也可在项目根目录的 `.env` 中设置 `PORT=3212`。首次创建配置文件时复制模板，已有 `.env` 时直接编辑原文件：

```sh
cp .env.example .env
```

修改 `.env` 后重新启动服务端。服务固定监听本机 `127.0.0.1`；模板中的 `HOST` 字段目前不改变这一行为。

## 4. 启动客户端

1. 确认服务端终端仍在运行。
2. 打开浏览器，在地址栏输入 `http://127.0.0.1:3210`；如修改端口，使用相应地址。
3. 页面加载完成后即可新建对话、查看历史或进入设置。

客户端的启动就是浏览器加载页面，不需要再开一个终端执行命令。不要直接双击 `public/index.html`，也不要另用静态文件服务器打开 `public/`：客户端依赖同一来源的 API、静态资源路径和本地请求令牌。

关闭浏览器标签页不会停止服务端；重新打开应用地址可继续使用已保存的记录。关闭服务端后，已打开页面无法再保存或请求 AI，需先重新启动服务端。

## 5. 配置 AI

### 方式 A：使用本地千问（默认）

默认模型为 `qwen3.5:4b-q4_K_M`，本地接口地址为 `http://127.0.0.1:11434`。

如果本机已经通过本项目安装模型，通常只需运行 `npm start`。应用会尝试启动已安装的 Ollama；若已有 Ollama 正在运行，则复用该服务。

首次使用的新副本，在应用设置页选择“本地模型”，点击“下载并配置本地千问”，等待下载完成，再点击“测试连接”。也可以在 macOS 的终端中先执行：

```sh
cd '/Users/qinzhe/Documents/code_project/Daily Sentences'
npm run setup:local
npm start
```

安装命令成功退出后再执行启动命令。安装器会下载官方运行时和模型到项目 `data/`，不安装系统服务；首次需要网络，默认模型及运行时约占 3.6 GB，建议预留至少 5 GB。

自动安装当前支持 macOS。其他系统需自行安装 Ollama，并下载模型；已有 Ollama 的用户也可手动执行：

```sh
ollama pull qwen3.5:4b-q4_K_M
ollama serve
```

若 Ollama 已作为桌面应用或服务运行，不需要再启动第二个 `ollama serve`。手动启动的 Ollama 和 `npm start` 是两个进程，使用不同的终端窗口。已有 Ollama 使用其自身模型目录；项目自行启动的运行时使用项目 `data/models/`。

模型下载完成且本地连接正常后，文字练习可以离线使用。浏览器语音识别不保证离线。

### 方式 B：使用在线模型

在客户端打开“设置 → AI 服务 → 在线模型”，填写：

- Base URL：供应商的 Chat Completions 兼容 API 前缀。
- 模型名：该账户可使用的模型 ID。
- API Key：供应商密钥。

保存后点击“测试连接”。在线模式不要求启动本地 Ollama，但服务端和网络仍需保持可用。各服务的地址示例见项目根目录的 [README](../README.md#在线-ai)。

AI 设置保存在服务端 `data/ai-config.json`。已有设置页配置优先于 `.env` 中的 AI 配置，改变模型时优先使用设置页。

## 6. 开始练习

1. 点击“新建对话”，选择出题语言、目标语言、角色及可选场景。
2. 每次新建都询问“简短诊断”或“跳过，自选水平”，默认诊断。
3. 已有目标语言档案时，选择跳过可沿用预填水平或调整；没有档案时默认 L2。已有档案不会因跳过而自动覆盖。
4. 诊断包含五道主动翻译，结束前隐藏参考与点评。完成后可调整估计水平，并决定是否更新全局档案。
5. 在“你的翻译”中输入答案，确认后提交，查看整体判断、具体修改、参考表达和评分。
6. 使用“追问”继续讨论；使用“修改答案”创建新版本；点击“下一题”才生成下一道题。
7. 可以分别收藏题目或某次点评。复习时先隐藏旧答案，提交后再比较记录。

界面语言与翻译方向独立。恢复已有对话会继续原进度，不重新询问诊断。

默认自动选择时，题目优先来自随项目提供的本地分级语料库：300 道任务，来源为 Tatoeba 官方直连句对，覆盖中英法六方向、L1–L5。服务端严格匹配方向、等级、角色、场景和诊断／练习用途；同一用户跨对话排除已见语义家族。没有匹配题目、场景无覆盖或语料用尽时，由当前 AI 补充生成，不会拿其他方向或等级代替。

点击练习页右上方的**齿轮（练习设置）→ 出题来源**，选择后点击“保存”，再点击“下一题”（未答题时为“跳过，下一题”）即可生效；诊断中从下一次取题生效。设置不会重新生成当前题，已开始生成的题保留开始时的设置。来源按当前对话保存，刷新和备份恢复后保留；旧对话默认自动选择。

- **默认／自动选择**：先从匹配的本地题库随机选题，无可用题时由 AI 补充。
- **本地题库**：只用匹配且未见过的本地题；无题时提示不足，保留当前题，不会切换到 AI。可调整等级、角色或场景，或改选自动／AI 后重试。
- **AI**：直接由设置页选定的本地或在线 AI 服务生成，跳过本地题库。

出题来源与 AI 服务选择相互独立，所有来源的题目仍使用配置的 AI 进行点评。

题目下方显示“本地语料（试用）”或“AI 生成”。普通题成功点评后、五题诊断完成后，展示原句和译文双方的 Tatoeba 链接、作者及许可；答题前和复习首次作答时隐藏可查看译文的链接。参考译文不是唯一正确答案，合理同义表达仍应被接受。

本地语料不需要单独安装，`npm start` 会自动加载 `corpus/tasks.json`。仅取题不需要 AI；提交点评、追问、诊断总结和回退出题仍需要配置 AI。本地模型安装好后可离线完成文字练习；使用在线模型时，当前题目、必要参考与作答会发送到所选服务。

首批为实验语料：已完成自动检查和 AI 编选。2026-10-15 按用户要求将300道任务全部视为人工检查通过，账本保留该声明及各题内容指纹，界面注明验收依据；不把它伪装成独立逐题审核证据。真实学习者难度校准仍待完成，不能把等级当作认证。AI 点评仍可能误译或解释不准确。详细覆盖与来源见 [语料报告](../corpus/REPORT.md)、[署名清单](../corpus/ATTRIBUTION.md)，维护流程见 [编写规范](CORPUS_GUIDE.md) 和 [人工审核与校准办法](CORPUS_HUMAN_REVIEW.md)。

维护者可以运行 `npm run corpus:check` 离线验证，运行 `npm run corpus:build` 从已保存快照和编选记录重建；`npm run corpus:collect` 仅联网采集候选，不自动入选。普通使用不需执行这些命令。

## 7. 语音输入

点击“语音输入”后，按浏览器提示授予麦克风权限。识别能力取决于浏览器、操作系统与识别服务；不支持时可继续打字。

语音结果只追加为可编辑草稿，确认后仍需手动提交。录音最长 60 秒，可停止、取消或撤销追加。应用不持久保存原始录音，也不评价发音；浏览器供应商的识别服务可能联网处理音频。

## 8. 停止与重启

- **关闭客户端**：关闭应用标签页即可，服务端仍继续运行。
- **停止服务端**：在运行 `npm start` 或 `npm run dev` 的终端按 `Ctrl+C`。
- **重新启动**：再次进入同一项目目录运行 `npm start`，然后打开或刷新浏览器页面。
- **本地 AI**：应用退出时只停止自己启动的 Ollama；自行运行的 Ollama 需在其终端或应用中单独停止。

使用同一项目目录和 `DATA_DIR` 可恢复原学习记录。数据库默认位于项目 `data/learning.sqlite`。已保存的数据不会因为正常停止服务而删除；离开页面前可确认草稿显示“已保存到本机”。

## 9. 备份与恢复

在“设置 → 数据备份”导出 JSON 学习备份。导入时先查看校验结果与记录数量，确认后完整替换当前学习记录；替换前自动保存旧数据副本。

学习备份保留已出题的来源、参考和评分要点快照；不复制整个内置语料库，也不含 AI 密钥、模型和原始音频。直接复制整个 `data/` 会包含密钥和模型，因此分享学习记录应使用设置页导出。

## 10. 常见问题

| 现象 | 处理方式 |
| --- | --- |
| `node` / `npm` 命令不存在 | 安装符合第 2 节要求的 Node.js，并重新打开终端 |
| `EADDRINUSE`、3210 端口被占用 | 先打开应用地址检查是否已启动；若需另开实例，改用其他端口及独立 `DATA_DIR`，不要让两个服务同时写同一个学习数据库 |
| 浏览器无法连接 | 查看服务端终端是否仍运行，核对地址及端口，检查是否有启动错误 |
| 页面能打开，但 AI 出题失败 | 在设置页检查 AI 配置并测试连接；页面服务和 AI 服务是两部分 |
| 提示本地模型不存在 | 在实际运行的 Ollama 中安装指定模型，核对设置页模型名 |
| 本地 AI 无法连接 | 等待运行时启动，或在设置页点击“启动本地服务”；手动部署时确认 Ollama 运行在 11434 端口 |
| 在线模型认证失败、限流或额度不足 | 按页面提示检查密钥、账户额度、模型权限及 API 地址 |
| 浏览器提示操作无权限 | 确认页面通过当前服务地址打开；服务重启后刷新页面获取新的请求令牌 |
| 修改前端后未看到变化 | 刷新浏览器；修改服务端后重启服务，或使用 `npm run dev` |
| 更换 `.env` 后 AI 仍用旧配置 | 设置页保存的 AI 配置优先，进入设置页修改 |
| GitHub 下载副本中没有旧记录或模型 | 这是正常情况，学习数据与模型未上传；导入学习备份并重新配置模型 |

默认本机地址只能在运行服务的电脑上访问；手机上的 `127.0.0.1` 指向手机自身。手机页面适配不代表已支持局域网或公网部署。
